## 📌 Project Overview

Traditional Large Language Models (LLMs) like GPT or LLaMA are capable of producing fluent natural language responses, but they are prone to hallucinations, lack domain-specific precision, and often give outdated information. When answering scientific or academic queries, accuracy and verifiable sources are non-negotiable.

This project implements a **Retrieval-Augmented Generation (RAG)** system designed to act as a virtual research assistant. By indexing over 50,000 papers from the **arXiv Open Access Dataset**, the system retrieves relevant document excerpts (titles, abstracts, comments) and grounds **LLaMA 3** (served locally via Ollama) to answer scientific queries with inline citations and verifiable reference lists.

---

## ✨ Key Features

- **Citation-Grounded Answers:** Answers generated by LLaMA 3 are strictly tied to retrieved scientific literature with inline citation tags (`[1]`, `[2]`).
- **Dense Vector Retrieval:** Uses `SentenceTransformers` (`all-MiniLM-L6-v2`) and **FAISS** for fast L2 similarity vector searches across scientific chunks.
- **Local & Private LLM Execution:** Serves LLaMA 3 locally using **Ollama**, ensuring complete data privacy and zero API costs.
- **Real-Time Streaming Interface:** Interactive ChatGPT-like chat interface built with **Streamlit**, supporting real-time response streaming and persistent session memory.
- **Automated Reference Mapping:** Automatically parses model outputs to convert `[arXiv:ID]` metadata tags into clean numerical bibliography references displayed beneath the response.

## 📁 Repository Structure

```text
.
├── app.py              # Main Streamlit application entry point & chat UI
├── data_loader.py      # Module for loading saved preprocessed chunks & FAISS index
├── retriever.py        # Dense vector retrieval & similarity search logic
├── llama_qa.py         # Prompt engineering, Ollama API integration, streaming & citation mapping
├── requirements.txt    # Python dependencies
└── README.md           # Project documentation
```

### Module Overview

- **`data_loader.py`**: Handles loading the FAISS vector index and metadata mapping files from local storage.
- **`retriever.py`**: Encodes the incoming query and performs top-$k$ nearest neighbor search on the FAISS index.
- **`llama_qa.py`**: Constructs grounded prompts combining retrieved context and the query, manages streaming responses from the Ollama local server, and post-processes citations.
- **`app.py`**: Renders the Streamlit frontend UI, manages `st.session_state` for conversation history, and displays reference blocks.

## 🚀 Getting Started

### Prerequisites

1. **Python 3.9+** installed on your system.
2. **Ollama** installed and running locally.
   - Download from [ollama.ai](https://ollama.ai/)
   - Pull the LLaMA 3 model:
     ```bash
     ollama pull llama3
     ```

### Installation

1. **Clone the repository:**
   ```bash
   git clone https://github.com/your-username/scientific-qna-assistant.git
   cd scientific-qna-assistant
   ```

2. **Create a virtual environment:**
   ```bash
   python -m venv venv
   source venv/bin/activate  # On Windows: venv\Scripts\activate
   ```

3. **Install dependencies:**
   ```bash
   pip install -r requirements.txt
   ```

4. **Ensure Vector Index & Data Chunks are available:**
   *Note: Due to GitHub file size limits (>100MB), the pre-built FAISS index must be downloaded or generated locally using the preprocessing script.*

5. **Run the Streamlit App:**
   ```bash
   streamlit run app.py
   ```

## ⚠️ Challenges & Limitations

- **Hardware Dependency & Latency:** Local LLaMA 3 generation time (~10–15 seconds per query) depends heavily on GPU/CPU availability.
- **Large Storage Footprint:** The vector index (over 200MB for 50k papers) exceeds GitHub's standard upload limits (requires Git LFS or external data hosting).
- **Post-Processing Complexity:** Parsing dynamic model responses to convert raw arXiv identifiers into structured, numbered references requires precise regex post-processing.
